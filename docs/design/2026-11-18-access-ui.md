# Access UI intent

Subject: a household member deciding which browsers and assistants may act for them.
Emotional target: calm control.

Use the existing warm green Home OS palette: surface #fafbf8, text #17201a, accent #315f49, and the existing line, muted-text, warning and dark-mode tokens. Keep the current system/sans typography, 13px supporting copy, 16px section headings, 20px identity heading, and 44px touch controls. Do not add images or a second visual system.

Layout: retain the Account panel's divided sections. Identity and sign-out lead; assistant setup and simple role explanations precede two flat, paged access rosters. Owners choose a household person above the rosters. Consent is a narrow document with identity, destination and capability review before explicit Allow/Deny actions. At 390px and 320px, rows wrap into a single readable column with no horizontal scrolling.

Signature element: a quiet green status label beside each named connection, paired with an explicit End access control. Labels distinguish Authorized, Not used yet and Ended; no implied presence tracking.

Accessibility: semantic headings, labelled controls, visible focus, readable wrapping of untrusted client names/hosts, live status/error copy, and actual forms for personal-action links. Opening a link never approves, resets credentials, or asks for push permission.

Browser inspection is owned by the parent U7 verification phase. Final self-critique will record source and component evidence separately from browser evidence.

## Browser refinement

The actual 320px consent capture showed a long per-operation list pushing the decision several screens down. Keep the same surface and tokens, show concise capability groups first, and retain every exact permission in a native expandable details control. Summaries derive from the returned capabilities; unknown permissions still prevent approval. Keep the server address readable on narrow screens and describe lasting sign-in without internal coordination terminology.

## Definition-of-Done self-critique

Squint: source-level hierarchy remains one divided Account surface with identity, assistant setup and flat rosters; consent has one reading column and two explicit decision controls. No new accent, gradient, illustration, nested dashboard cards or decorative chrome was introduced. Actual squint inspection in a browser is deferred to U7.

Skim: headings say Connect an assistant, Browser sessions, Assistant connections, Staying signed in and Your password. Connection labels say Authorized, Not used yet or Ended. Unverified names, verified domain, return destination, local-address warning and the signed-in person precede consent decisions. Component tests verify this text and control hierarchy.

Above fold: identity and sign-out lead Account. Consent leads with the person and review purpose; its decision controls follow the client/destination/capability review intentionally. On short screens the person scrolls through the review before Allow. CSS uses wrapping and a one-column details layout at 390px; 320px, actual fold position and keyboard focus visibility still require U7 browser inspection.

Slop fingerprint: the design reuses Home OS tokens, borders, typography and button language. There are no generic hero slogans, dashboard tiles, generated art, animated ornament or invented presence indicators. Roster names and dates carry the useful information. Browser evidence is not claimed by this document.
